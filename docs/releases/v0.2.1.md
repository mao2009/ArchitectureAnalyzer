# ArchitectureAnalyzer v0.2.1

ArchitectureAnalyzer 0.2.1 is the stable release of the feature set exercised by
`v0.2.1-rc1`, plus correctness fixes merged after that release candidate.

## Highlights

- Architecture Contract schemas v1 through v5 remain supported; versionless contracts remain v1.
- Schema v2: strict architecture coverage through `unclassifiedCode` / AARC010.
- Schema v3: positive dependency allowlists through `allowedDependencies`.
- Schema v4: deterministic declared-graph DAG validation through
  `dependencyGraph.requireAcyclic` / AARC011.
- Schema v5: narrow, justified AARC002/AARC003 architecture exceptions.
- Multi-project compilation scoping verified with real Producer/Consumer/Tests/Tooling builds.
- Stable baseline / ratcheting support through `architecture.baseline.json`.
- `loach.ArchitectureAnalyzer.Baseline` provides the `architecture-baseline` dotnet tool.
- Representative performance regression guard covers 300 files / roughly 900 source types.

## Diagnostics

0.2.1 contains AARC001 through AARC012 as normal analyzer diagnostics plus generator-only AARC013.

New since stable 0.1.0:

- AARC010 — type is not assigned to an architecture layer under strict coverage.
- AARC011 — declared allowed-dependency graph contains a cycle.
- AARC012 — architecture baseline is invalid or ambiguous.
- AARC013 — baseline capture transport used only by the baseline generator.

## Changes since v0.2.1-rc1

- AARC002 now covers delegate declarations and attribute type references.
- Supported contract schemas fail closed on unknown JSON properties rather than silently ignoring
  likely typos. Reserved `$` / `x-` metadata remains intentionally extensible.
- README and reference documentation were aligned with actual AdditionalFiles, generic API-name,
  and conditional-marker behavior.

## Migration from 0.1.0

Existing 0.1.0 consumers do not need to rewrite their contract to upgrade.

1. Change `loach.ArchitectureAnalyzer` to version `0.2.1`.
2. Keep the existing schema-v1/versionless contract initially; it remains supported.
3. Adopt schema v2-v5 features only when needed.
4. If existing violations block adoption, install
   `loach.ArchitectureAnalyzer.Baseline` 0.2.1 and generate a reviewed baseline.
5. No-contract compilations remain intentional no-ops.

## Compatibility and validation

The release line is covered by:

- unit and compatibility tests;
- real architecture build gate;
- multi-project isolation gate;
- baseline generation / ratcheting / pruning gate;
- representative performance regression guard;
- Linux and Windows packed-NuGet consumer E2E.

## Known follow-up

Issue #76 tracks an enhancement to warn when a well-formed contract entry semantically matches
nothing in a compilation (for example a misspelled namespace root or API type). This is not a
schema parse failure and remains a follow-up design item.
